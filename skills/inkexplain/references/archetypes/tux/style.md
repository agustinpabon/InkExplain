# Tux Style

Sparse hand-drawn article sketches in which Tux performs one cognitive action inside an original physical metaphor. Recognition comes from Tux's marker set in `identity.md`, not from rendering detail.

## Canvas

- 16:9 horizontal article illustration by default.
- White or very light background with generous whitespace.
- One core idea and one enlarged action subject: Tux's main action takes about 35–55% of the canvas.
- Leave empty space around Tux's action so the metaphor reads at a glance.

## Linework

- Rough black hand-drawn linework with visible human looseness.
- Tux simplified for article explanation: keep every identity marker and drop rendering detail.
- No gradients, shadows, paper texture, or polished vector finish.

## Color

- Black: main strokes, objects, Tux's body, and labels.
- White: Tux's face patches and belly.
- Yellow-orange: only Tux's beak and oversized webbed feet.
- Red, orange, or blue: restrained accents for motion, stamps, warning marks, source tags, or decisive emphasis, used only when they clarify the action.

## Labels

- Usually two to six short labels, copied exactly in the user's language.
- Rough handwriting, never clean digital type.
- Keep labels clear of Tux's eyes, beak, belly, flippers, and feet.

## Avoid

- Dense PPT-like diagrams or infographics, formal diagrams, crowded nodes, poster layouts, top-left titles, and dense text blocks.
- UI screenshots, CLI screenshots, kernel dashboards, web hero graphics, product posters, and operating-system marketing graphics.
- Logos and badges of any kind: distro logos, distro badges, package-manager marks, or Linux Foundation logos.
- Generic tech-mascot or stock-illustration rendering.
